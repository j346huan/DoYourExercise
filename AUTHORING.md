# Authoring

## Textbooks

Each textbook has a folder such as `content/Atiyah69/`, with `book.json` containing its ID, title, authors, year, cover path, publication details, and chapters. The About page formats references from these fields and uses the book ID as the citation label. The `publication` object contains `publisher` and optional `address`, `series`, `volume`, and `doi` fields. Omit a chapter's `sections` field if the book numbers exercises directly within chapters.

## Exercise files

```text
content/Atiyah69/Atiyah69-1-1/
  meta.json
  statement.tex
  proof.tex
  proof.lean
  translation.tex
  verification.json
```

Only `meta.json` and `statement.tex` are required. Leave the statement file empty when the question has not yet been entered.

```json
{
  "tag": "1.1",
  "chapter": "1",
  "section": null,
  "number": "1",
  "title": "",
  "status": "unsolved",
  "updated": "2026-09-05",
  "dependencies": [],
  "lean": null
}
```

Use an empty title unless the textbook names that individual exercise. Book and chapter identifiers determine the folder and page name; dots become dashes. There are no topic tags.

- `statement.tex`: question only.
- `proof.tex`: natural-language proof. Set `status` to `solved`, or keep it `unsolved` with `"coverage": "partial"` for partial notes.
- `proof.lean`: optional Lean 4 proof.
- `translation.tex`: explanation of the Lean proof, required when Lean code is present.
- `verification.json`: generated by `npm run lean:check`; never edit manually.

Use UTF-8 TeX fragments without a document preamble, custom macro definitions, or packages. Supported syntax includes paragraphs, `$...$`, `\(...\)`, `\[...\]`, `$$...$$`, equation/align/gather environments, `\textbf`, `\emph`, `\textit`, `\texttt`, and simple enumerate/itemize lists. Math is rendered by KaTeX.

Write `\exref{1.1}` for a same-book exercise or `\exref{Atiyah69,1.1}` for a cross-book reference. Dependencies in metadata use full identities such as `"Atiyah69,1.1"`. All references must resolve.

The searchable catalog includes statements and metadata. Proofs, Lean code, and translations are loaded separately.

## Proof style

Keep proofs concise, rigorous, and limited to the mathematical question. Use new notation only when it is reused enough to shorten the argument.

Use `$...$` for inline math, `:` rather than `\colon`, `\to` for arrows, `\mathbb` for number fields, and `\cong` for isomorphisms. Put each needed unnumbered display on a single source line, `\[equation\]`. Keep equations on one code line, avoid unnecessary displays, and omit equation tags.

## Lean files

A proof for `Atiyah69,1.1` uses the generated module name `LeanExercises.Atiyah69.Ex_1_1`:

```json
"lean": {
  "module": "LeanExercises.Atiyah69.Ex_1_1",
  "verified": false
}
```

Run `npm run lean:prepare` to generate the module copies. Later proofs can import an earlier module or Mathlib directly. After `npm run lean:check` succeeds, set `status` to `formalized` only if the theorem matches the question. Changing any Lean source, toolchain, or dependency configuration invalidates previous evidence.

## Checks

```sh
npm run content:build
npm test
npm run typecheck
npm run build
```

Commit canonical content and code. Keep generated output, credentials, `.env` files, `.lake/`, `node_modules/`, and `.tools/` out of the repository.
